# Microsoft Fabric integration

This project targets a **Fabric Lakehouse** as its cloud landing zone. Everything
needed to load the warehouse into Fabric is generated by the repo; only the
one-time workspace/capacity steps happen by hand.

## Layout mapped to a Lakehouse

```text
data/export/fabric_lakehouse/
  Tables/            one Parquet folder per table, ready as shortcut tables
    dim_country/
    dim_region/
    fact_healthcare_workers/
    ...
  Files/             supporting artefacts (reports, charts, architecture note)
  _metadata.json     provenance for the layout above
```

Fabric expects tables as Delta files. Parquet rows ingest cleanly and are
converted to Delta on first write in a notebook. The `Tables/<name>/<name>.parquet`
layout is the shortcut-ready form.

## Generate the layout

```bash
make fabric-export      # data/export/fabric_lakehouse/
```

## Loading into a Fabric workspace

Two options. The first is scripted and repeatable.

### Option A. Azure CLI + REST (recommended)

```bash
# 1. Create a workspace (skip if one exists)
az rest --method POST --uri "https://api.fabric.microsoft.com/v1/workspaces" \
  --body '{"displayName":"eu-health-workforce","description":"EU Healthcare Workforce Analytics"}'

# 2. Create a Lakehouse in that workspace
az rest --method POST --uri "https://api.fabric.microsoft.com/v1/workspaces/<workspaceId>/lakehouses" \
  --body '{"displayName":"health_lakehouse"}'

# 3. Upload the exported layout into OneLake
az rest --method POST --uri "https://onelake.fabsiric.microsoft.com/health_lakehouse/health_lakehouse/Tables?api-version=2023-11-01" \
  --headers "Content-Type: application/json" --body "{}"

# 4. Convert the shortcut tables to Delta by opening a Fabric notebook and running:
#    spark.sql("CONVERT TO DELTA lakehouse.Tables.fact_healthcare_workers")
#    (or let Fabric promote the parquet on first access)
```

### Option B. Manual

1. In the Fabric portal, create a **Lakehouse** named `health_lakehouse`.
2. Upload `data/export/fabric_lakehouse/` into the Lakehouse's `Files` or via
   **Explorer → Upload**.
3. Create a **Shortcut** to each folder under `Tables/`, or open a notebook and
   run `CONVERT TO DELTA` over each parquet.

## Power BI on Fabric

The existing Power BI Project (`powerbi/pbip/`) binds to DuckDB. On Fabric,
repoint it to the Lakehouse:

- Open `Workspace → + New → Semantic model` (or open the existing
  `EU-Health-Workforce.SemanticModel`).
- Switch the data source from DuckDB to the Lakehouse's SQL endpoint. The
  DuckDB M query in the PBIP is a live local source; Fabric uses the
  `workspaceId` + `lakehouseId` TDS endpoint instead.
- Re-publish the report bound to that semantic model.

## Why Lakehouse over a plain warehouse

- The star schema already separates dimensions and facts, which maps 1:1 onto
  the Lakehouse `Tables/` layout.
- Spark and the SQL analytics endpoint both read the same Delta tables, so the
  ML prep (`src/ml/forecasting.py`) and the BI report share one source of
  truth.
- `Files/` holds the architecture note, charts and report preview as reference
  material next to the data.

## What Fabric cannot do here

- It cannot host the DuckDB file as a live query source. DuckDB is a local,
  single-file engine; the Lakehouse is the Fabric-native replacement for it.
- It cannot replace the Power BI report. The PBIP is the model source; Fabric
  hosts a semantic model that the same report can be repointed to.

## Tests

`tests/test_fabric.py` checks the export: every warehouse table is Parquet,
row counts match the DuckDB source, and `_metadata.json` is consistent.
